📅 Customer Meetings

Schedule, Track, and Manage Client Meetings

📋 Overview

Customer Meetings is a comprehensive meeting management system for financial advisors to schedule, track, and manage all client interactions. The system supports multiple meeting types, modes, and status tracking with complete audit trail.

📅 Meeting Scheduling

Schedule meetings with date, time, duration, and location/link. Supports in-person, video call, and phone call modes.

📝 Meeting Types

5 meeting types: Portfolio Review, Financial Planning, Client Onboarding, Grievance Resolution, and General Meeting.

✅ Status Tracking

Track meeting lifecycle: Scheduled → Completed/Cancelled. Add notes, outcomes, and cancellation reasons.

📊 Meeting History

View upcoming and past meetings with complete history. Filter by customer, date range, type, and status.

📈 Meeting Summary

Dashboard showing total meetings, next scheduled meeting, last completed meeting, and status breakdown.

🔔 Upcoming Dashboard

View all upcoming meetings across customers with days-until indicators for today, tomorrow, and this week.

🏷️ Meeting Types, Modes & Statuses

Meeting Types

The system supports 5 types of customer meetings:

Type Code Display Label Description
review Portfolio Review Regular portfolio performance review meetings with customers
planning Financial Planning Comprehensive financial planning sessions (goals, insurance, tax, estate)
onboarding Client Onboarding Initial onboarding meetings for new customers (KYC, risk profiling, documentation)
grievance Grievance Resolution Meetings to address customer complaints, concerns, or issues
other General Meeting Any other type of customer meeting not covered above

Meeting Modes

Meetings can be conducted in 3 different modes:

Mode Code Display Label Icon Required Field
in_person In-Person 📍 MapPin meeting_location (text)
video_call Video Call 📹 Video meeting_link (url) - Zoom, Google Meet, etc.
phone_call Phone Call 📞 Phone None (phone number already in customer profile)

Meeting Statuses

Meeting lifecycle tracked through 4 statuses:

Status Code Display Label Color Description
scheduled Scheduled Blue (Info) Meeting is scheduled for future. Can be edited, completed, or cancelled.
completed Completed Green (Success) Meeting completed. Has completed_at timestamp, optional notes and outcome.
cancelled Cancelled Red (Error) Meeting cancelled. Has cancelled_at timestamp and required cancellation_reason.
rescheduled Rescheduled Yellow (Warning) Meeting was rescheduled. Typically followed by creating a new meeting.

MeetingsList.tsx

Purpose: Main container component for displaying and managing all customer meetings.

Location: Embedded in CustomerViewPage.tsx "Meetings" tab

Key Features:

  • Tab Navigation: "Upcoming" and "Past" tabs with count badges
  • Upcoming Filter: Shows meetings with status='scheduled' AND scheduled_date >= today

  • Empty States: Friendly messages when no meetings in filtered view
  • React Query Integration: Auto-refetch on mutations for real-time updates

MeetingCard.tsx

Purpose: Display individual meeting details with action buttons.

Display Sections:

  • Header: Meeting type label + status badge
  • Details Grid: Date, Time & Duration, Mode icon + label, Location/Link
  • Agenda: Highlighted section with blue left border
  • Notes: Expandable "Show Notes" / "Hide Notes" toggle (for completed meetings)
  • Outcome: Green highlighted section (for completed meetings)
  • Cancellation Reason: Red highlighted section (for cancelled meetings)

Action Buttons (conditional):

  • Edit: Only for scheduled meetings, opens CreateMeetingModal in edit mode
  • Complete: Only for scheduled, marks as completed with notes/outcome
  • Cancel: Only for scheduled, marks as cancelled with reason
  • Delete: Available for all meetings, removes from database

CreateMeetingModal.tsx

Purpose: Form modal for creating new meetings or editing existing ones.

Modes:

  • Create Mode: When opened without meeting prop
  • Edit Mode: When opened with existing meeting prop (pre-populates form)

Form Fields:

Query Hooks:

Mutation Hooks:

Query Invalidation:

💾 Database Table: t_customer_meetings

Purpose: Store all customer meeting records with scheduling, tracking, and audit information.

CREATE TABLE t_customer_meetings ( id SERIAL PRIMARY KEY, tenant_id INTEGER NOT NULL REFERENCES t_tenants(id), is_live BOOLEAN NOT NULL, customer_id INTEGER NOT NULL REFERENCES t_customers(id) ON DELETE CASCADE, -- Meeting details meeting_type VARCHAR(50) NOT NULL CHECK (meeting_type IN ('review', 'planning', 'onboarding', 'grievance', 'other')), meeting_mode VARCHAR(20) NOT NULL CHECK (meeting_mode IN ('in_person', 'video_call', 'phone_call')), -- Scheduling scheduled_date DATE NOT NULL, scheduled_time TIME NOT NULL, duration_minutes INTEGER DEFAULT 60, -- Status tracking status VARCHAR(20) NOT NULL DEFAULT 'scheduled' CHECK (status IN ('scheduled', 'completed', 'cancelled', 'rescheduled')), -- Location/Link (based on meeting_mode) meeting_location TEXT, -- For in_person meetings meeting_link TEXT, -- For video_call meetings -- Meeting content agenda TEXT, notes TEXT, outcome TEXT, -- Completion/Cancellation tracking completed_at TIMESTAMP, cancelled_at TIMESTAMP, cancellation_reason TEXT, -- Audit fields created_by INTEGER NOT NULL REFERENCES t_users(id), created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP );

Key Columns

Column Type Description
scheduled_date DATE Date of meeting (ISO format: 2025-12-25)
scheduled_time TIME Time of meeting (HH:MM format: 14:30)
duration_minutes INTEGER Meeting duration in minutes (default: 60)
meeting_location TEXT Physical address for in-person meetings
meeting_link TEXT Video call URL (Zoom, Google Meet, etc.)
agenda TEXT Meeting agenda/topics to discuss
notes TEXT Meeting notes added during/after meeting
outcome TEXT Meeting outcome/summary (for completed meetings)
completed_at TIMESTAMP Timestamp when meeting was marked completed
cancelled_at TIMESTAMP Timestamp when meeting was cancelled
cancellation_reason TEXT Reason for cancellation (required when cancelling)

Indexes

-- Performance indexes CREATE INDEX idx_customer_meetings_customer ON t_customer_meetings(tenant_id, is_live, customer_id); CREATE INDEX idx_customer_meetings_scheduled_date ON t_customer_meetings(scheduled_date); CREATE INDEX idx_customer_meetings_status ON t_customer_meetings(status); CREATE INDEX idx_customer_meetings_upcoming ON t_customer_meetings(tenant_id, is_live, status, scheduled_date) WHERE status = 'scheduled';

Triggers

-- Auto-update updated_at timestamp CREATE TRIGGER trigger_update_customer_meetings_timestamp BEFORE UPDATE ON t_customer_meetings FOR EACH ROW EXECUTE FUNCTION update_customer_meetings_timestamp();

Trigger Explanation: Automatically updates updated_at column to CURRENT_TIMESTAMP whenever any row is updated.

👥 User Workflows

Workflow 1: Scheduling a New Meeting

  1. Navigate to Customer View Page → Meetings Tab
  2. Click "Schedule Meeting" button (top right)
  3. CreateMeetingModal opens with empty form
  4. Fill in required fields:
    • Meeting Type: Select from dropdown (Review, Planning, Onboarding, Grievance, Other)
    • Meeting Mode: Select In-Person, Video Call, or Phone Call
    • Date: Pick date from date picker
    • Time: Pick time from time picker
    • Duration: Enter minutes (default 60)
  5. Conditionally fill:
    • If In-Person: Enter meeting location (office address, etc.)
    • If Video Call: Enter meeting link (Zoom URL, Google Meet link)
  6. Optionally add Agenda (meeting topics, discussion points)
  7. Click "Schedule Meeting" button
  8. Meeting created with status='scheduled' and appears in "Upcoming" tab

Workflow 2: Editing a Scheduled Meeting

  1. In Meetings Tab → Upcoming, locate the meeting card
  2. Click "Edit" button on meeting card
  3. CreateMeetingModal opens in edit mode with pre-populated data
  4. Modify any fields (date, time, location, agenda, etc.)
  5. Click "Update Meeting" button
  6. Meeting updated in database, UI refreshes with new details

Workflow 3: Completing a Meeting

  1. In Meetings Tab → Upcoming, locate the meeting card
  2. Click "Complete" button (green checkmark icon)
  3. Confirmation dialog appears: "Mark this meeting as completed?"
  4. User prompted for optional Notes (meeting discussion summary)
  5. User prompted for optional Outcome (action items, decisions made)
  6. Click "Complete" button in dialog
  7. Backend:
    • Sets status = 'completed'
    • Sets completed_at = CURRENT_TIMESTAMP
    • Stores notes and outcome
  8. Meeting moves from "Upcoming" tab to "Past" tab
  9. Meeting card displays green "Completed" badge
  10. Notes and outcome visible in expandable sections

Workflow 4: Cancelling a Meeting

  1. In Meetings Tab → Upcoming, locate the meeting card
  2. Click "Cancel" button (red X icon)
  3. Confirmation dialog appears: "Are you sure you want to cancel this meeting?"
  4. User prompted for Cancellation Reason (REQUIRED)
  5. Example reasons: "Client unavailable", "Advisor schedule conflict", "Meeting postponed"
  6. If reason is empty, validation fails: "Cancellation reason is required"
  7. Click "Yes, Cancel" button
  8. Backend:
    • Sets status = 'cancelled'
    • Sets cancelled_at = CURRENT_TIMESTAMP
    • Stores cancellation_reason
  9. Meeting moves from "Upcoming" tab to "Past" tab
  10. Meeting card displays red "Cancelled" badge
  11. Cancellation reason visible in red highlighted section

Workflow 5: Deleting a Meeting

  1. In Meetings Tab (Upcoming or Past), locate the meeting card
  2. Click Delete icon (trash can)
  3. Browser confirmation: "Are you sure you want to delete this meeting?"
  4. Click "OK" to confirm
  5. Meeting permanently removed from database
  6. UI updates immediately, meeting card disappears
  7. Warning: This action is irreversible

Workflow 6: Viewing Past Meetings

  1. Navigate to Customer View Page → Meetings Tab
  2. Click "Past" tab (shows count badge)
  3. View list of:
    • Completed meetings (green badge)
    • Cancelled meetings (red badge)
    • Scheduled meetings with date < today (missed meetings)
  4. Past meeting cards show:
    • All meeting details (date, time, mode, location/link)
    • Agenda (if provided)
    • For Completed: Expandable notes section, outcome summary
    • For Cancelled: Cancellation reason
  5. Past meetings have limited actions (only Delete available)
