2️⃣ Goal Types

1. Time-Based Goal 📅

Concept: Fixed target date, flexible corpus amount.

Question: "If I invest ₹10,000/month for 15 years, how much will I have?"

Use Case: Retirement planning (retire in 2045), Child's 18th birthday fund.

Calculation:
Projected Corpus = FV(current_value, monthly_SIP, years_to_target, expected_return_rate)

Formula: FV = PV × (1 + r)^n + PMT × [((1 + r)^n - 1) / r]
Where: PV = current value, PMT = monthly SIP, r = monthly return rate, n = months

2. Price-Based Goal 💰

Concept: Fixed target amount, flexible achievement date.

Question: "When will I reach ₹50 lakhs at my current investment pace?"

Use Case: House down payment (₹20L), Wedding fund (₹15L).

Calculation:
Months to Achievement = NPER(target_amount, current_value, monthly_SIP, expected_return_rate)
Projected Date = Today + Months to Achievement

Formula: n = log[(target / PV) × (r / PMT) + 1] / log(1 + r)
Where: target = target amount, PV = current value, PMT = monthly SIP, r = monthly return

3. Time & Price Goal 🎯

Concept: Fixed target date AND fixed target amount. System performs gap analysis.

Question: "I need ₹1 Crore by 2035. Am I on track?"

Use Case: Child's education (₹50L by 2030), Retirement corpus (₹2Cr by 2045).

Calculations:
1. Projected Corpus = FV(current_value, current_monthly_SIP, years_to_target, expected_return)
2. Required Monthly SIP = PMT(target_amount, current_value, years_to_target, expected_return)
3. Monthly SIP Gap = Required SIP - Current SIP
4. Corpus Gap = Target Amount - Projected Corpus
5. Progress % = (Projected Corpus / Target Amount) × 100
6. On Track = (Corpus Gap <= 5% of Target)
7. Probability of Success = Monte Carlo simulation (considering market volatility)

Action Logic:
- If SIP Gap > 0: Recommend increasing SIP by gap amount
- If Corpus Gap > 20%: Recommend rebalancing to higher return schemes
- If both gaps exist: Suggest extending timeline or reducing target

3️⃣ Business Logic & Calculations

Goal Creation Flow

  1. User selects goal type → Modal shows appropriate form
  2. User enters goal details: Name, target date/amount, expected return (12% default), inflation rate (6% default)
  3. User links portfolio schemes: Select schemes and allocation % (e.g., 40% of HDFC Equity = Education goal)
  4. System calculates current value: Sums allocated portions from customer portfolio
  5. System calculates monthly contribution: Sums SIP amounts from linked schemes
  6. Backend runs calculations: Uses goal.calculator.service.ts formulas
  7. System stores goal: In t_jtbd_configurations with config_data as JSONB
  8. System creates snapshot: First entry in t_goal_progress_snapshots

Goal Tracking & Recalculation

When does recalculation happen?

  • Manual Trigger: User clicks "Recalculate" button
  • Scheduled Job: Monthly cron job (goal.recalculation.job.ts) runs at 2 AM on 1st of month
  • Transaction Event: When new SIP/redemption happens in linked schemes
  • Portfolio Rebalance: When allocation percentages change

Recalculation Process

  1. Fetch customer's portfolio holdings (from t_portfolio_holdings OR calculate from transactions + NAV)
  2. Calculate current value: Sum of (scheme units × latest NAV × allocation %)
  3. Calculate monthly contribution: Sum of SIP amounts for linked schemes
  4. Run goal-specific formulas based on goal type
  5. Compare with previous snapshot:
    • If deviation > 10%: Generate alert
    • If behind schedule: Auto-add to watchlist
    • If milestone approaching (within 3 months): Generate reminder
  6. Save new snapshot to t_goal_progress_snapshots
  7. Update config_data in t_jtbd_configurations

Alert Generation Logic

Condition Alert Type Severity Action Required
Corpus gap > 20% CORPUS_SHORTFALL HIGH Increase SIP or rebalance
Behind schedule by 6+ months TIMELINE_DELAY HIGH Increase contribution
Deviation increased from last month DEVIATION_INCREASED MEDIUM Review and recalculate
Milestone within 90 days MILESTONE_APPROACHING LOW Review progress
Probability of success < 50% LOW_SUCCESS_PROBABILITY HIGH Revise goal or increase SIP

Portfolio Allocation Tracking

Problem: Customer has ₹10L portfolio. They create goals totaling ₹15L in allocations. System must prevent over-allocation.

Allocation Validation:

  1. Get customer's total portfolio value per scheme (e.g., HDFC Equity = ₹5L)
  2. Sum all existing goal allocations for that scheme (e.g., Education goal = 40%, Retirement goal = 30% = 70% used)
  3. Calculate available allocation: 100% - 70% = 30% available
  4. When creating new goal: Ensure allocation % ≤ available %
  5. Show UI: "₹1.5L available (30% of ₹5L HDFC Equity)"

Component: AssetAllocationUtilization.tsx shows this as a pie chart

4️⃣ Database Tables

📊 Table: t_jtbd_configurations

Purpose: Main storage for all goals (Goals are stored as JTBD type = 'goal_tracking')

Column Type Description
id SERIAL PRIMARY KEY Unique goal ID
customer_id INTEGER (FK) Which customer owns this goal
jtbd_type VARCHAR(50) Always 'goal_tracking' for goals
title VARCHAR(255) Goal name (e.g., "Child's Education Fund")
config_data JSONB Stores entire goal configuration: goal_type, target_date, target_amount, projected_corpus, monthly_contribution, linked_schemes[], etc.
is_watchlisted BOOLEAN Is this goal in watchlist for quick monitoring
watchlist_auto_added BOOLEAN Was it auto-added (because it's behind schedule)?
next_alert_date DATE Next date to generate alert (for recurring reminders)
is_active BOOLEAN Soft delete flag (archived goals)

Example config_data:

📊 Table: t_goal_progress_snapshots

Purpose: Historical tracking of goal progress (one snapshot per month per goal)

Column Type Description
id SERIAL PRIMARY KEY Snapshot ID
goal_id INTEGER (FK) References t_jtbd_configurations(id)
snapshot_date DATE Date of this snapshot (usually 1st of month)
current_value NUMERIC(15,2) Portfolio value allocated to this goal on snapshot_date
monthly_contribution NUMERIC(15,2) SIP amount at this snapshot
projected_corpus NUMERIC(15,2) Projected final value at target date
projected_achievement_date DATE For price-based goals: when will target be achieved
probability_of_success NUMERIC(5,2) % probability of achieving goal (0-100)
on_track BOOLEAN Is goal on track to achieve target?
deviation_percentage NUMERIC(5,2) +ve = ahead of schedule, -ve = behind schedule
recalculation_trigger VARCHAR(50) What triggered this snapshot: 'manual', 'scheduled_job', 'transaction_event'

Usage: GoalProgressChart.tsx queries this table to plot progress over time.

📊 Table: t_goal_scheme_allocations

Purpose: Links goals to portfolio schemes (many-to-many relationship)

Column Type Description
id SERIAL PRIMARY KEY Allocation ID
goal_id INTEGER (FK) References t_jtbd_configurations(id)
scheme_id INTEGER (FK) References t_schemes(id)
allocation_percentage NUMERIC(5,2) What % of this scheme is for this goal (0-100)
notes TEXT Optional notes about this allocation

Example:

  • Goal: "Education Fund" (goal_id=5)
  • Linked to: HDFC Equity (scheme_id=101, allocation=60%), ICICI Bluechip (scheme_id=102, allocation=40%)
  • Means: 60% of customer's HDFC Equity holdings + 40% of ICICI Bluechip holdings = Education Fund corpus

📊 Table: t_goal_alerts

Purpose: Stores alerts generated for goals

Column Type Description
id SERIAL PRIMARY KEY Alert ID
goal_id INTEGER (FK) References t_jtbd_configurations(id)
customer_id INTEGER (FK) For quick customer-level queries
alert_type VARCHAR(50) 'corpus_shortfall', 'timeline_delay', 'deviation_increased', 'milestone_approaching', 'low_success_probability'
severity VARCHAR(20) 'high', 'medium', 'low'
message TEXT Human-readable alert message
action_required VARCHAR(100) 'increase_sip', 'rebalance_portfolio', 'extend_timeline', 'reduce_target'
action_details JSONB Specific recommendations: {"recommended_sip_increase": 2500, "from": 25000, "to": 27500}
is_acknowledged BOOLEAN Has user seen/acknowledged this alert?
acknowledged_at TIMESTAMP When was it acknowledged

Display: GoalAlertBanner.tsx shows unacknowledged alerts.

6️⃣ Financial Formulas Used

Future Value (FV) - For Time-Based Goals

FV = PV × (1 + r)^n + PMT × [((1 + r)^n - 1) / r] Where: - FV = Future Value (projected corpus) - PV = Present Value (current portfolio value) - PMT = Periodic Payment (monthly SIP) - r = Periodic Interest Rate (annual_return_rate / 12 / 100) - n = Number of Periods (years × 12) Example: PV = ₹5,00,000 PMT = ₹10,000/month r = 12% p.a. = 1% per month = 0.01 n = 15 years = 180 months FV = 500000 × (1.01)^180 + 10000 × [((1.01)^180 - 1) / 0.01] FV ≈ 29,59,918 + 49,95,802 = ₹79,55,720

Number of Periods (NPER) - For Price-Based Goals

n = log[(FV / PV) × (r / PMT) + 1] / log(1 + r) Where: - n = Number of months to achieve target - FV = Future Value (target amount) - PV = Present Value (current value) - PMT = Monthly SIP - r = Monthly interest rate Example: FV = ₹50,00,000 PV = ₹5,00,000 PMT = ₹10,000 r = 1% per month n = log[(5000000/500000) × (0.01/10000) + 1] / log(1.01) n ≈ 183 months ≈ 15.25 years Achievement Date = Today + 15.25 years

Payment (PMT) - For Time & Price Goals

PMT = (FV - PV × (1 + r)^n) × [r / ((1 + r)^n - 1)] Where: - PMT = Required monthly SIP - FV = Target amount - PV = Current value - r = Monthly interest rate - n = Months to target date Example: FV = ₹1,00,00,000 (target) PV = ₹10,00,000 (current) r = 1% per month n = 20 years = 240 months PMT = (10000000 - 1000000 × (1.01)^240) × [0.01 / ((1.01)^240 - 1)] PMT ≈ ₹21,850/month (required SIP) If current SIP = ₹15,000/month Monthly Gap = 21850 - 15000 = ₹6,850/month shortfall

Inflation Adjustment

Real Value = Nominal Value / (1 + inflation_rate)^years Example: Projected Corpus = ₹1 Crore (after 20 years) Inflation Rate = 6% p.a. years = 20 Real Value = 10000000 / (1.06)^20 Real Value ≈ ₹31,18,047 (in today's money) Purchasing Power Lost = 10000000 - 3118047 = ₹68,81,953 (68.82%)

7️⃣ User Workflows

Workflow 1: Creating a New Goal

  1. Navigate to Customer → Goals tab → Click "Add Goal"
  2. Modal opens (GoalSetupModal.tsx)
  3. Enter goal name: "Child's Education"
  4. Select goal type: "Time & Price Goal"
  5. Enter target date: "2030-06-01"
  6. Enter target amount: "₹50,00,000"
  7. Set expected return: 12% (default)
  8. Link schemes:
    • HDFC Equity: 60% allocation
    • ICICI Bluechip: 40% allocation
  9. System calculates:
    • Current value = ₹2,50,000 (from portfolio)
    • Monthly contribution = ₹8,000 (SIPs)
    • Projected corpus = ₹48,50,000 (calculation)
    • Corpus gap = -₹1,50,000 (shortfall)
    • Required SIP = ₹9,200/month
    • SIP gap = +₹1,200/month needed
  10. Click "Create Goal"
  11. Goal saved → Alert shown: "Increase SIP by ₹1,200/month to stay on track"

Workflow 2: Monitoring Goals

  1. GoalProgressTracker shows:
    • Total Goals: 5
    • On Track: 3 (green)
    • Needs Attention: 2 (yellow/red)
  2. Click on goal card → Opens GoalDetailsModal
  3. View progress chart showing actual vs projected growth
  4. See alerts: "Corpus gap increased by 2% this month"
  5. Review recommended actions: "Increase SIP by ₹1,500 OR extend timeline by 6 months"

Workflow 3: Recalculation

  1. Customer makes new SIP transaction in linked scheme
  2. System detects transaction event
  3. Triggers recalculation:
    • Fetches updated portfolio value
    • Recalculates monthly contribution
    • Runs formulas again
    • Compares with previous snapshot
    • Generates alert if deviation increased
  4. GoalRecalculationModal shows before/after comparison
  5. New snapshot saved to database
