🎛️ Cruise Control

Centralized Monitoring & Management Hub for Daily Operations

📋 Overview

Cruise Control is a centralized dashboard for monitoring and managing all automated background operations in the KewalInvest platform. It provides real-time visibility into NAV downloads, market data synchronization, portfolio snapshots, and alert systems.

📊 NAV Downloads

Monitor daily NAV downloads for all bookmarked mutual fund schemes. Track pending downloads, failures, and data gaps with actionable insights.

📈 Market Downloads

Track End-of-Day (EOD) market index downloads (NSE, BSE). Monitor download status and identify missing data for performance analysis.

🔔 Alerts

Centralized view of all customer alerts from JTBD system (goal alerts, transaction alerts, profile triggers) for quick acknowledgment and action.

📸 Portfolio Snapshots

Automated monthly/weekly snapshots of customer portfolios for performance tracking and historical analysis. Supports backfill and regeneration.

⚙️ Settings

Configure default market index for performance benchmarking and other system-wide preferences.

2. Portfolio Snapshot Service

File: backend/src/services/portfolioSnapshot.service.ts

Key Methods:

  • generateSnapshots(): Main method called by scheduler - generates snapshots for all customers
  • calculateSnapshotData(): Calculates portfolio value, invested amount, gains, XIRR for a customer
  • smartBackfill(): Intelligently fills gaps in historical snapshots
  • dropAllSnapshots(): Deletes all snapshots for a tenant
  • regenerateAllSnapshots(): Drop + recreate all snapshots

Business Logic:

  • Queries all active customers for tenant
  • For each customer, calculates total portfolio value using latest NAV data
  • Aggregates all holdings, transactions, and fund manager allocations
  • Stores monthly snapshot in t_customer_portfolio_snapshots
  • Logs execution details in t_portfolio_snapshot_executions

3. Portfolio Snapshot Scheduler

File: backend/src/services/portfolioSnapshotScheduler.service.ts

Purpose: Manages cron-based scheduling for automated snapshot generation.

Features:

  • Registers with Generic Job Scheduler system
  • Default schedule: Weekly (Friday 9 PM) or Monthly (1st of month)
  • Supports custom cron expressions
  • Automatic retry on failure (max 3 retries)
  • Execution logging with success/failure tracking

4. Generic Job Scheduler Service

File: backend/src/services/jobScheduler.service.ts

Purpose: Unified job scheduling system for all background jobs.

Supported Job Types:

  • PORTFOLIO_SNAPSHOT: Monthly/weekly portfolio snapshots
  • NAV_DOWNLOAD: Daily NAV downloads (managed separately by navScheduler.service.ts)
  • MARKET_EOD_DOWNLOAD: Daily market EOD downloads (pending implementation)
  • ALERT_GENERATION: Daily alert generation for JTBD (pending implementation)

Key Features:

  • Cron-based scheduling using Node.js setTimeout
  • Tenant-isolated job execution
  • Retry mechanism with exponential backoff
  • Execution history tracking
  • Statistics aggregation (total, successful, failed, running)

💾 Database Tables

1. t_portfolio_snapshot_configs

Purpose: Stores scheduler configuration for portfolio snapshot jobs.

CREATE TABLE t_portfolio_snapshot_configs ( id SERIAL PRIMARY KEY, tenant_id INTEGER NOT NULL REFERENCES t_tenants(id), user_id INTEGER NOT NULL REFERENCES t_users(id), is_live BOOLEAN NOT NULL, schedule_type VARCHAR(20) NOT NULL DEFAULT 'weekly', cron_expression VARCHAR(100) NOT NULL DEFAULT '0 21 * * 5', -- Friday 9 PM is_enabled BOOLEAN NOT NULL DEFAULT true, last_executed_at TIMESTAMP, next_execution_at TIMESTAMP, execution_count INTEGER NOT NULL DEFAULT 0, failure_count INTEGER NOT NULL DEFAULT 0, max_retries INTEGER NOT NULL DEFAULT 3, created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP, updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP, CONSTRAINT unique_snapshot_scheduler UNIQUE(tenant_id, is_live), CONSTRAINT valid_schedule_type CHECK (schedule_type IN ('weekly', 'monthly', 'custom')) );

Key Columns:

  • schedule_type: 'weekly', 'monthly', or 'custom'
  • cron_expression: Cron format for scheduling (e.g., '0 21 * * 5' = Friday 9 PM)
  • is_enabled: Whether scheduler is active
  • last_executed_at: Timestamp of last successful execution
  • next_execution_at: Calculated next execution time

2. t_portfolio_snapshot_executions

Purpose: Logs every snapshot job execution with detailed results.

CREATE TABLE t_portfolio_snapshot_executions ( id SERIAL PRIMARY KEY, scheduler_config_id INTEGER NOT NULL REFERENCES t_portfolio_snapshot_configs(id) ON DELETE CASCADE, tenant_id INTEGER NOT NULL, is_live BOOLEAN NOT NULL, execution_time TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP, status VARCHAR(20) NOT NULL, -- 'success', 'failed', 'running', 'retrying', 'skipped' trigger_source VARCHAR(20) NOT NULL, -- 'scheduled', 'manual' snapshot_month_end DATE, customers_processed INTEGER DEFAULT 0, customers_failed INTEGER DEFAULT 0, snapshots_created INTEGER DEFAULT 0, snapshots_updated INTEGER DEFAULT 0, retry_attempt INTEGER DEFAULT 0, error_message TEXT, error_details JSONB, execution_duration_ms INTEGER, started_at TIMESTAMP, completed_at TIMESTAMP, created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP );

Key Columns:

  • status: Execution outcome (success/failed/running/retrying/skipped)
  • trigger_source: 'scheduled' (auto) or 'manual' (user-triggered)
  • snapshot_month_end: Month-end date for which snapshots were generated
  • customers_processed: Number of customers successfully processed
  • snapshots_created/updated: New vs existing snapshots
  • execution_duration_ms: Time taken for execution

3. t_customer_portfolio_snapshots

Purpose: Stores monthly/weekly portfolio snapshot data for each customer.

CREATE TABLE t_customer_portfolio_snapshots ( id SERIAL PRIMARY KEY, tenant_id INTEGER NOT NULL REFERENCES t_tenants(id), is_live BOOLEAN NOT NULL, customer_id INTEGER NOT NULL REFERENCES t_customers(id) ON DELETE CASCADE, snapshot_month_end DATE NOT NULL, -- Portfolio Metrics total_invested_amount NUMERIC(15,2) NOT NULL, total_current_value NUMERIC(15,2) NOT NULL, total_unrealized_gain NUMERIC(15,2) NOT NULL, gain_percentage NUMERIC(10,4) NOT NULL, xirr NUMERIC(10,4), -- Holdings Breakdown total_holdings INTEGER NOT NULL DEFAULT 0, active_schemes INTEGER NOT NULL DEFAULT 0, -- Fund Manager Allocation (Top 5) fund_manager_allocation JSONB, -- Audit created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP, updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP, CONSTRAINT unique_customer_snapshot UNIQUE(tenant_id, is_live, customer_id, snapshot_month_end) );

Key Columns:

  • snapshot_month_end: Date of snapshot (typically last day of month)
  • total_invested_amount: Sum of all purchase amounts
  • total_current_value: Current market value of all holdings
  • total_unrealized_gain: Current value - Invested amount
  • xirr: Extended Internal Rate of Return (annualized return %)
  • fund_manager_allocation: JSONB storing top 5 fund managers with allocation %

4. t_job_scheduler_configs (Generic)

Purpose: Generic scheduler configuration for all job types.

CREATE TABLE t_job_scheduler_configs ( id SERIAL PRIMARY KEY, tenant_id INTEGER NOT NULL REFERENCES t_tenants(id), job_type VARCHAR(50) NOT NULL REFERENCES m_job_types(code), user_id INTEGER NOT NULL REFERENCES t_users(id), is_live BOOLEAN NOT NULL, schedule_type VARCHAR(20) NOT NULL DEFAULT 'weekly', cron_expression VARCHAR(100) NOT NULL, is_enabled BOOLEAN NOT NULL DEFAULT true, max_retries INTEGER NOT NULL DEFAULT 3, job_config JSONB, -- Job-specific flexible configuration last_executed_at TIMESTAMP, next_execution_at TIMESTAMP, execution_count INTEGER DEFAULT 0, failure_count INTEGER DEFAULT 0, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, CONSTRAINT unique_job_scheduler_config UNIQUE(tenant_id, job_type, is_live) );

5. t_job_executions (Generic)

CREATE TABLE t_job_executions ( id SERIAL PRIMARY KEY, scheduler_config_id INTEGER NOT NULL REFERENCES t_job_scheduler_configs(id) ON DELETE CASCADE, job_type VARCHAR(50) NOT NULL REFERENCES m_job_types(code), tenant_id INTEGER NOT NULL, is_live BOOLEAN NOT NULL, execution_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP, status VARCHAR(20) NOT NULL, trigger_source VARCHAR(20) NOT NULL, retry_attempt INTEGER DEFAULT 0, execution_data JSONB, -- Job-specific execution results error_message TEXT, error_details JSONB, execution_duration_ms INTEGER, started_at TIMESTAMP, completed_at TIMESTAMP, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP );

⏰ Job Scheduler System

Overview

Cruise Control integrates with the Generic Job Scheduler system for managing all background jobs. The scheduler supports multiple job types with cron-based scheduling, retry logic, and execution tracking.

Job Types

Job Type Description Default Schedule Status
PORTFOLIO_SNAPSHOT Generate monthly/weekly portfolio snapshots Weekly (Friday 9 PM) LIVE
NAV_DOWNLOAD Daily NAV downloads for bookmarked schemes Daily (6 AM) LIVE
MARKET_EOD_DOWNLOAD Daily market EOD downloads for indices Daily (6 PM) PENDING
ALERT_GENERATION Generate alerts from JTBD configurations Daily (12 AM) PENDING

Scheduler Architecture

┌─────────────────────────────────────────────────┐ │ Generic Job Scheduler Service │ │ (jobScheduler.service.ts) │ ├─────────────────────────────────────────────────┤ │ - Job Registration │ │ - Cron Management (Node.js setTimeout) │ │ - Retry Logic (max 3 retries) │ │ - Execution Logging │ │ - Statistics Aggregation │ └─────────────────────────────────────────────────┘ ↓ ┌───────────────┬───────────────┬───────────────┐ ↓ ↓ ↓ ↓ Portfolio NAV Market Alert Snapshot Scheduler EOD Scheduler Generator Scheduler ✅ ⚠️ ⚠️ ✅

Execution Flow

  1. Config Creation: Admin creates scheduler config via Cruise Control UI
  2. Registration: Job registered with Generic Scheduler (cron expression, job_type)
  3. Scheduling: Scheduler calculates next_execution_at and sets Node.js timer
  4. Execution: At scheduled time, job handler invoked
  5. Logging: Execution details logged to t_job_executions
  6. Retry (if failed): Automatic retry up to max_retries (3)
  7. Statistics: Aggregated stats available via /api/jobs/statistics/:jobType

Cron Expression Examples

Expression Description Use Case
0 21 * * 5 Every Friday at 9:00 PM Weekly portfolio snapshots
0 0 1 * * 1st day of every month at 12:00 AM Monthly snapshots
0 6 * * * Every day at 6:00 AM Daily NAV downloads
0 18 * * * Every day at 6:00 PM Daily market EOD downloads
0 0 * * * Every day at 12:00 AM Daily alert generation

👥 User Workflows

Workflow 1: Setting Up Portfolio Snapshot Scheduler (Admin)

  1. Navigate to Cruise Control → Portfolio Snapshots Tab
  2. Click "Create Configuration" button
  3. Select schedule type:
    • Weekly: Default Friday 9 PM
    • Monthly: Default 1st of month 12 AM
    • Custom: Enter custom cron expression
  4. Click "Enable Scheduler" toggle
  5. Save configuration
  6. Scheduler auto-calculates next_execution_at and displays it
  7. Snapshots will be generated automatically at scheduled time

Workflow 2: Manual Portfolio Snapshot Generation (Admin)

  1. Navigate to Cruise Control → Portfolio Snapshots Tab
  2. Click "Execute Snapshot" button
  3. Confirm execution (generates snapshots for last month-end)
  4. View real-time progress in execution history table
  5. Check results: Customers processed, Snapshots created/updated, Duration

Workflow 3: Backfilling Historical Snapshots (Admin)

  1. Navigate to Cruise Control → Portfolio Snapshots Tab
  2. Scroll to "Backfill Snapshots" section
  3. Select Start Date and End Date (month-end dates)
  4. (Optional) Specify customer IDs to backfill only certain customers
  5. Click "Smart Backfill"
  6. System generates snapshots for all months in range
  7. View execution details in history table

Workflow 4: Monitoring NAV Downloads (All Users)

  1. Navigate to Cruise Control → NAV Tab
  2. View statistics: Total Active, Pending, Failed, Metrics Pending
  3. Use filter buttons to view specific categories (e.g., Failed Downloads)
  4. Click on a scheme card to view details
  5. Click "Download NAV" to manually trigger download for that scheme
  6. View updated status after download completes

Workflow 5: Monitoring Market Downloads (All Users)

  1. Navigate to Cruise Control → Market Tab
  2. View statistics: Total Indices, Download Completed, Pending, Failed
  3. Filter indices by download status
  4. Click "Download EOD" to manually trigger download for an index
  5. View latest download date and data gaps

Workflow 6: Managing Alerts (All Users)

  1. Navigate to Cruise Control → Alerts Tab
  2. View all active alerts (Goal Due, JTBD Trigger, Goal Progress)
  3. Filter by status: All, Active, Acknowledged, Dismissed
  4. Click "Acknowledge" to mark alert as seen
  5. Click "Dismiss" to hide alert
  6. View customer details and alert message

Workflow 7: Setting Default Index (Admin)

  1. Navigate to Cruise Control → Settings Tab
  2. Locate "Default Index Settings" section
  3. Open dropdown showing all market indices (NSE/BSE)
  4. Select desired benchmark index (e.g., NIFTY 50, SENSEX)
  5. Click "Save"
  6. Default index used for performance comparisons across platform
