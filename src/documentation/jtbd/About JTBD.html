2️⃣ JTBD Types

1. Portfolio Alert 📊

Purpose: Track expected transactions in customer portfolio and alert when they deviate from pattern.

Use Case: Monthly SIP tracking, quarterly redemptions, annual rebalancing.

Configuration Fields:

  • scheme_code: Which scheme to monitor (e.g., HDFC Equity INF200K01234)
  • txn_type: Transaction type (Purchase, Redemption, Switch-In, Switch-Out, Dividend Reinvestment)
  • frequency: Expected frequency (Daily, Fortnightly, Monthly, Quarterly, Yearly, NA)
  • day_of_month: Expected day (e.g., 5 for 5th of month)
  • deviation_days: Alert if transaction doesn't occur within X days (e.g., ±3 days)
  • amount: Expected transaction amount
  • track_till_months: How long to monitor (e.g., 60 months for 5 years of SIP)

Business Logic:

Example: Monthly SIP Alert - Scheme: HDFC Equity - Txn Type: Purchase (SIP) - Frequency: Monthly - Day of Month: 5 - Deviation: ±3 days (alert if no transaction between 2nd-8th) - Amount: ₹10,000 - Track Till: 60 months (5 years) System checks: 1. Every month on 9th: Query transactions for scheme between 2nd-8th 2. If NO transaction found: Generate alert "SIP not executed" 3. If transaction found with amount ≠ ₹10,000: Generate alert "SIP amount mismatch" 4. Next alert date = 5th of next month 5. Continue for 60 months, then auto-deactivate

2. Time-Based Alert 📅

Purpose: Fixed date reminders for one-time or recurring tasks.

Use Case: Annual portfolio review, quarterly rebalancing, tax filing reminders.

Configuration Fields:

  • alert_date: Day of month (1-31)
  • alert_month: Month (1-12, or ALL for recurring)
  • is_recurring: One-time or repeating annually

Business Logic:

Example 1: Annual Review (Recurring) - Alert Date: 15 - Alert Month: 3 (March) - Is Recurring: true System generates alert every March 15th for annual portfolio review. Example 2: One-Time Reminder (Non-recurring) - Alert Date: 25 - Alert Month: 12 - Is Recurring: false System generates alert on December 25th, then auto-deactivates.

3. Profile Trigger 🎂

Purpose: Alerts based on customer profile milestones.

Use Case: Birthday reminders, anniversary wishes, relationship milestones.

Configuration Fields:

  • trigger_type: "birthday" or "anniversary"
  • days_before: Alert X days before the event (e.g., 7 days before birthday)

Business Logic:

Example: Birthday Alert - Trigger Type: birthday - Days Before: 7 System logic: 1. Fetch customer DOB from t_customers.date_of_birth 2. Calculate next birthday: - If DOB = 1990-05-15 and today = 2025-11-05 - Next birthday = 2026-05-15 3. Calculate alert date = Next birthday - 7 days = 2026-05-08 4. Generate alert on 2026-05-08: "Rajesh Kumar's birthday in 7 days" 5. After birthday passes, calculate next year's alert

3️⃣ Business Logic & Workflows

Creating a JTBD

  1. User selects customer from CustomerViewPage
  2. Clicks "Add JTBD" → JTBDSetupModal opens
  3. Selects JTBD type: Portfolio Alert, Time-Based, or Profile Trigger
  4. Fills type-specific form:
    • Portfolio Alert: Select scheme, txn type, frequency, amount
    • Time-Based: Select date, month, recurring
    • Profile Trigger: Select trigger type (birthday/anniversary), days before
  5. Sets priority: Critical, High, Medium, Low
  6. Backend validates:
    • For Portfolio Alerts: Checks if scheme exists in customer's portfolio
    • For Profile Triggers: Checks if customer has DOB/anniversary date
  7. System calculates next_alert_date:
    • Portfolio Alert: Next expected transaction date ± deviation
    • Time-Based: Next occurrence of alert_date/alert_month
    • Profile Trigger: Event date - days_before
  8. Saves to t_jtbd_configurations with config_data as JSONB
  9. Updates customer record: jtbd_count++, has_jtbd_setup=true

Alert Generation & Display

How Alerts Are Generated:

  1. Daily cron job (or real-time trigger) checks t_jtbd_configurations
  2. Finds JTBDs with next_alert_date = Today or past due
  3. For each JTBD:
    • Portfolio Alert: Check if transaction occurred within deviation range
    • Time-Based: Generate reminder alert
    • Profile Trigger: Generate milestone reminder
  4. Creates alert entry in t_goal_alerts table
  5. Calculates next alert date and updates t_jtbd_configurations
  6. Frontend displays via:
    • JTBDDashboardPage → Upcoming Alerts section
    • CustomerViewPage → JTBD summary badge
    • Cruise Control → AlertsTab (future implementation)

Alert Lifecycle

Status Description Actions Available
Scheduled JTBD is active, waiting for next_alert_date Edit, Delete, Deactivate
Triggered Alert generated, waiting for acknowledgment Acknowledge, Dismiss, View Details
Acknowledged User has seen alert, action taken View History
Expired Portfolio Alert tracked for track_till_months, auto-deactivated Reactivate, Delete

Integration with Goals

Important Note: JTBD and Goals share the same t_jtbd_configurations table!

Goals are stored with jtbd_type = 'goal_tracking'

Alerts (JTBD) are stored with jtbd_type = 'portfolio_alert' | 'time_based' | 'profile_trigger'

Both use t_goal_alerts table for generated alerts.

4️⃣ Database Tables

📊 Table: t_jtbd_configurations

Purpose: Stores all JTBD alert configurations (also used for Goals)

Column Type Description
id SERIAL PRIMARY KEY Unique JTBD ID
customer_id INTEGER (FK) Which customer this JTBD belongs to
jtbd_type VARCHAR(50) 'portfolio_alert', 'time_based', 'profile_trigger', 'goal_tracking'
title VARCHAR(255) JTBD title (e.g., "Monthly SIP Tracking - HDFC Equity")
priority VARCHAR(20) 'critical', 'high', 'medium', 'low'
is_active BOOLEAN Is this JTBD currently active?
config_data JSONB Type-specific configuration (see examples below)
next_alert_date DATE When should next alert be triggered
is_watchlisted BOOLEAN Pinned to watchlist for quick access

Example config_data (Portfolio Alert):

{ "scheme_code": "INF200K01234", "scheme_name": "HDFC Equity Fund - Direct - Growth", "folio_no": "12345678", "txn_type_id": 1, "txn_type": "Purchase", "frequency": "monthly", "day_of_month": 5, "deviation_days": 3, "amount": 10000, "track_till_months": 60 }

Example config_data (Time-Based):

{ "alert_date": 15, "alert_month": 3, "is_recurring": true }

Example config_data (Profile Trigger):

{ "trigger_type": "birthday", "days_before": 7 }

📊 Table: t_goal_alerts

Purpose: Stores generated alerts for both JTBD and Goals

Column Type Description
id SERIAL PRIMARY KEY Alert ID
goal_id INTEGER (FK) References t_jtbd_configurations(id)
customer_id INTEGER (FK) For quick customer queries
alert_type VARCHAR(50) 'transaction_missed', 'amount_mismatch', 'time_based_reminder', 'birthday_reminder', 'anniversary_reminder'
severity VARCHAR(20) 'high', 'medium', 'low'
message TEXT Human-readable alert message
action_required VARCHAR(100) 'contact_customer', 'verify_transaction', 'send_reminder'
is_acknowledged BOOLEAN Has alert been seen/acknowledged?
acknowledged_at TIMESTAMP When was it acknowledged

📊 Related Table: t_customers (JTBD Tracking Fields)

Customer table has JTBD-related fields:

  • jtbd_count: How many JTBDs configured for this customer
  • has_jtbd_setup: Quick flag for filtering customers without JTBD
  • date_of_birth: Used for birthday profile triggers
  • anniversary_date: Used for anniversary profile triggers
