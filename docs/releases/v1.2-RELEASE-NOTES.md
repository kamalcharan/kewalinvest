# Release Notes: v1.2 - Scheme-Based Asset Types

**Release Date:** 2026-01-17
**Migration File:** `v1.2-scheme-based-asset-types.sql`

---

## Summary

Replaces the single 'MF' (Mutual Fund) asset type with 42 AMFI scheme categories for accurate portfolio tracking and networth calculation.

---

## What's Changed

### 1. Asset Type Structure
- **Before:** All mutual funds categorized as single 'MF' asset type
- **After:** 42 distinct scheme categories from AMFI (Debt, Equity, Hybrid, Solution Oriented, Other)

### 2. Master Data (`m_asset_types`)
- Added 42 scheme categories with appropriate:
  - `asset_type_code` (e.g., "Debt Scheme - Liquid Fund")
  - `asset_type_name` (e.g., "Liquid Fund")
  - `category` (debt, equity, hybrid, fof, solution, commodity)
  - `default_assumption_rate` (expected returns)
- Legacy 'MF' asset type set to `is_active = false`

### 3. Database Changes
- FK constraint `t_scheme_details.scheme_category_id` now references `m_asset_types` (was `t_scheme_masters`)
- Updated `process_single_scheme_record` function for correct scheme category lookup

### 4. Import Behavior
- Scheme import now auto-populates `scheme_category_id` from mapped "Scheme Category" column
- Matches against `m_asset_types.asset_type_code`

## Verification Queries

```sql
-- Check scheme_category_id populated
SELECT
  COUNT(*) as total,
  COUNT(scheme_category_id) as has_category
FROM t_scheme_details;

-- Check FK constraint
SELECT conname, confrelid::regclass
FROM pg_constraint
WHERE conname = 't_scheme_details_scheme_category_id_fkey';
-- Expected: m_asset_types

-- Check asset type distribution
SELECT
  ma.asset_type_code,
  ma.category,
  COUNT(sd.id) as scheme_count
FROM m_asset_types ma
LEFT JOIN t_scheme_details sd ON sd.scheme_category_id = ma.id
WHERE ma.asset_type_code LIKE '%Scheme%'
GROUP BY ma.asset_type_code, ma.category
ORDER BY ma.category, ma.asset_type_code;
```
